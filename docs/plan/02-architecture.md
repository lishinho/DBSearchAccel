# DBSearchAccel 架构设计

## 一、整体架构

DBSearchAccel采用**分层解耦的模块化架构**，整体分为四层：

```
┌─────────────────────────────────────────────────────────────────┐
│ 接入层：业务系统、前端应用                                       │
└───────────────────┬─────────────────────────────────────────────┘
                    │
┌───────────────────▼─────────────────────────────────────────────┐
│ 核心业务层：接入网关 → 路由层 → 过滤规则层 → 数据聚合层 → 索引层  │
└───────────────────┬─────────────────────────────────────────────┘
                    │
┌───────────────────▼─────────────────────────────────────────────┐
│ 基础能力层：配置中心、实时缓存、降级熔断、插件中心、数据一致性校验 │
└───────────────────┬─────────────────────────────────────────────┘
                    │
┌───────────────────▼─────────────────────────────────────────────┐
│ 底层依赖层：关系型数据库、Elasticsearch、Redis、Canal、监控告警  │
└─────────────────────────────────────────────────────────────────┘
```

---

## 二、架构分层职责

### 2.1 接入层
| 组件 | 职责 |
|------|------|
| 业务系统 | 发起查询请求，接收中间件返回的结果 |
| 前端应用 | 无业务逻辑侵入，透明调用 |

### 2.2 核心业务层

| 模块 | 核心职责 |
|------|----------|
| 接入网关 | 统一入口、请求转发、负载均衡 |
| 路由层 | 场景路由、参数标准化、接口适配 |
| 过滤规则层 | 灰度规则、自定义过滤、SQL拼接 |
| 数据聚合层 | 全量+增量数据拼合、主键去重 |
| 索引层 | ES索引操作、Redis缓存操作 |

### 2.3 基础能力层

| 模块 | 核心职责 |
|------|----------|
| 配置中心 | 配置管理、热更新、灰度发布 |
| 实时缓存 | AOP拦截、主键缓存、过期策略 |
| 降级熔断 | 多级降级、熔断规则、兜底逻辑 |
| 插件中心 | 自定义插件、插件注册、插件执行 |
| 数据一致性校验 | 主键校验、字段校验、结果对比 |

### 2.4 底层依赖层

| 组件 | 职责 |
|------|------|
| 关系型数据库 | 数据存储（MySQL/OceanBase/PostgreSQL） |
| Elasticsearch | 索引存储、高性能查询 |
| Redis | 实时主键缓存 |
| Canal | Binlog监听、增量同步 |
| 监控告警 | Prometheus + Grafana + AlertManager |

## 三、核心业务流程

### 3.1 查询加速核心流程

```
业务系统
    │
    ▼
┌─────────────┐
│  接入网关   │ ← 请求校验、限流、负载均衡
└──────┬──────┘
       │
       ▼
┌─────────────┐
│   路由层    │ ← 场景匹配、参数标准化
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 过滤规则层  │ ← 灰度校验、DSL拼接
└──────┬──────┘
       │
       ├──────────────────┐
       │                  │
       ▼                  ▼
┌─────────────┐    ┌─────────────┐
│  索引层-ES  │    │ 索引层-Redis│
│ (全量主键)  │    │ (实时主键)  │
└──────┬──────┘    └──────┬──────┘
       │                  │
       └────────┬─────────┘
                │
                ▼
       ┌─────────────┐
       │ 数据聚合层  │ ← 拼合、去重、排序、分页
       └──────┬──────┘
              │
              ▼
       ┌─────────────┐
       │  数据库查询 │ ← 主键批量查询详情
       └──────┬──────┘
              │
              ▼
       ┌─────────────┐
       │ 过滤规则层  │ ← 后置过滤插件
       └──────┬──────┘
              │
              ▼
         返回结果
```

### 3.2 数据同步流程

```
┌─────────────────────────────────────────────────────────────┐
│                      数据同步流程                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  全量同步：                                                 │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐             │
│  │ 数据库   │───▶│  DataX   │───▶│   ES     │             │
│  └──────────┘    └──────────┘    └──────────┘             │
│                                                             │
│  增量同步：                                                 │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌───────┐│
│  │ 数据库   │───▶│  Canal   │───▶│   MQ     │───▶│  ES   ││
│  │ (Binlog) │    │ (监听)   │    │ (削峰)   │    │       ││
│  └──────────┘    └──────────┘    └──────────┘    └───────┘│
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.3 降级流程

```
正常流程：业务 → 网关 → 路由 → 过滤 → 索引 → 聚合 → 数据库
                    │
                    │ 触发降级
                    ▼
降级流程：业务 → 网关 → 降级熔断 → 原生数据库查询 → 返回
```

## 四、架构设计原则

| 原则 | 描述 |
|------|------|
| 无侵入性 | 不改变业务系统的原有架构和代码逻辑 |
| 分层解耦 | 各层、各模块之间通过标准化接口交互 |
| 配置化优先 | 所有可配置的规则均通过配置中心实现 |
| 可插拔扩展 | 核心能力通过插件化实现 |
| 高可用优先 | 所有核心流程均有兜底逻辑 |
| 性能优先 | 核心流程做轻量化设计 |
| 兼容性强 | 适配主流数据库、搜索引擎和缓存组件 |

## 六、高可用设计

### 6.1 部署高可用
- 集群部署：所有核心模块均支持集群部署
- 容器化：支持Docker/K8s部署
- 多可用区部署：支持跨可用区部署
- 数据持久化：ES集群模式、Redis主从+持久化

### 6.2 流程高可用
- 多级降级：接口/场景/全局三级降级
- 熔断保护：对异常/慢调用请求做熔断
- 异常重试：核心流程均做异常重试
- 空值兜底：ES/Redis查询结果为空时走数据库

### 6.3 数据高可用
- 最终一致性：全量+增量数据同步
- 数据校验：支持全量/增量数据一致性校验
- 同步重试：增量同步失败的任务存入消息队列重试
- 缓存容错：Redis故障时自动跳过缓存层
