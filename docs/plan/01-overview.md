# DBSearchAccel 项目概述

## 一、项目背景

### 1.1 问题陈述

在企业级业务系统中，基于MySQL、OceanBase、PostgreSQL等关系型数据库的业务场景，随着数据量和查询复杂度提升，**复杂多参数Where子句、多表联查、大数据量表的列表查询** 极易出现慢SQL问题。

传统优化手段存在以下瓶颈：
- 索引调优存在天花板
- 优化器索引选择错误
- 索引回查性能损耗
- 索引数量限制
- 业务侵入性高

### 1.2 解决方案

设计一款**轻量级、配置化、无侵入**的数据库复杂查询加速中间件，融合：
- **搜索引擎的高性能索引能力** - 用于条件过滤
- **关系型数据库的精准数据存储能力** - 用于数据详情查询

将优化维度从SQL升级为**数据索引维度**，一站式解决复杂场景慢SQL问题。

---

## 二、核心设计思想

| 设计原则 | 描述 |
|----------|------|
| 混合查询架构 | 用搜索引擎做高性能条件过滤（查主键ID），用关系型数据库做精准数据详情查询 |
| 实时性补全 | 通过缓存存储业务实时增删改的主键ID，补全搜索引擎数据同步的延时短板 |
| 配置化无侵入 | 所有规则通过配置中心实现，业务侧无需大幅修改代码 |
| 分层解耦设计 | 模块化、分层架构，各模块职责单一、可插拔 |
| 高可用兜底 | 多级降级、监控告警、数据一致性校验，故障时自动兜底 |

---

## 三、项目目标

### 3.1 性能目标
- 复杂查询耗时从**秒级降至毫秒级**
- 消除慢SQL告警

### 3.2 接入目标
- 业务侧通过配置即可完成基础接入
- 无需重构原有查询逻辑

### 3.3 适配目标
- 支持MySQL、OceanBase、PostgreSQL等主流关系型数据库
- 兼容Elasticsearch多版本

### 3.4 可用性目标
- 7*24小时稳定运行
- 故障自动降级
- 实时监控告警

## 四、项目定位

| 定位 | 说明 |
|------|------|
| 轻量级中间件 | 独立部署，支持单机/集群部署，容器化适配 |
| 查询加速专用 | 聚焦关系型数据库**复杂只读查询**加速 |
| 开源友好 | 基于主流开源技术栈构建，文档完善 |
| 中小企业友好 | 降低使用搜索引擎做查询加速的技术门槛 |

---

## 五、核心特性一览

| 特性 | 描述 |
|------|------|
| 混合查询加速 | Elasticsearch查主键+数据库查详情 |
| 全量+增量数据同步 | 支持全量数据初始化索引、基于Binlog的增量数据实时同步 |
| 实时缓存补全 | AOP拦截业务增删改操作，Redis缓存实时主键ID |
| 配置化路由/过滤 | 基于配置中心实现场景路由、查询过滤、灰度规则 |
| 多级降级兜底 | 支持接口级、场景级、全局级降级 |
| 多维度监控告警 | 采集QPS、延时、缓存命中率、ES查询成功率等指标 |
| 自定义插件扩展 | 支持自定义数据过滤插件、自定义降级插件 |
| 数据一致性校验 | 支持ES索引与数据库数据的主键/字段一致性校验 |
| 灰度放量 | 支持按商户/用户/流量的灰度准入 |

## 六、适用场景

### 6.1 典型适用场景
- 多条件组合查询（如电商订单筛选）
- 多表关联查询
- 大数据量分页查询
- 模糊搜索查询

### 6.2 不适用场景
- 简单的主键查询（直接查数据库更优）
- 高频写入场景（本中间件聚焦只读查询加速）
- 强实时性要求场景（存在毫秒级同步延迟）

---

## 七、项目来源

本项目基于蚂蚁集团adindex项目的核心设计理念，结合开源技术栈做适配与轻量化改造，旨在为中小企业提供一套易用、轻量的数据库查询加速解决方案。
